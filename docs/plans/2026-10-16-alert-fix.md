# Overlay GDI alert

The device dialog's expanded exception text identifies `Bitmap.GetHbitmap` →
`Overlay.SetFrame` → `Program.Tick` in the gaze engine. The hub/browser did not
raise the dialog. The WinForms modal blocked the UI timer while the separate
HTTP bus continued responding, so a healthy `/status` did not prove a working UI.
The triggering Windows display condition is not established. The device's GDI
count was low when inspected; resource exhaustion is not established either.

Fix lives in the sibling `era-gaze--wt-alert` worktree. Hiding now uses the
window's visibility instead of allocating undisposed blank bitmaps and converting
them every 16 ms. Frame conversion catches `ExternalException`, hides stale
pixels, logs at most once per 30 seconds, releases native resources and retries
on the next draw. Failed watch frames do not poison their redraw cache.

The hub payload and gate select the gaze worktree through `ERA_WT_SUFFIX`,
including its contract-source path and green stamp. Previously they always used
the main gaze checkout, which would have omitted this fix from a feature build.

Regression tests: the gaze repo's `tests/overlay-regression.ps1` compiles the actual
engine with a separate test entry point and runs real drawing plus injected
`GetHbitmap` failures. Run it on an interactive Windows desktop. For remote
execution, use `-CompileOnly`, then launch `real.exe <receipt>` and
`fault.exe <receipt> fault` as interactive one-shot tasks. Neither starts a
tracker, bus, or application lifecycle. The hub's assemble-suffix and gaze-recompile
suites cover source selection and recompilation on source changes.

Device evidence and final validation are recorded below when complete.
